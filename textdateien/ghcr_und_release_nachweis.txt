==================================================
1. Release Workflow
==================================================

Workflow:
GitHub Actions Release Workflow

Datei:
.pacman-app/.github/workflows/release.yml


Trigger:

Der Release Workflow wird nach einem erfolgreichen
Push auf den Branch main ausgeführt.

Zusätzlich ist ein manueller Start über
workflow_dispatch möglich.


Berechtigungen:

permissions:

contents: read
packages: write


Die Berechtigungen folgen dem Least-Privilege-Prinzip.
Der Workflow erhält nur die benötigten Rechte für das
Lesen des Repositorys und das Veröffentlichen von
Container Images in der GitHub Container Registry.



==================================================
2. Docker Image Build
==================================================

Das Docker Image der Pacman-Anwendung wird innerhalb
des Release Workflows automatisch erstellt.

Build-Befehl:

docker build \
-t pacman-app:${GITHUB_SHA} .


Der Commit-SHA wird als unveränderlicher Image-Tag
verwendet.

Dadurch bleibt jede veröffentlichte Image-Version
eindeutig nachvollziehbar.


Beispiel:

Image Tag:

e7c1216b2be3fc0549057c3e2cbf490f73d2b508



==================================================
3. Veröffentlichung nach GHCR
==================================================

Registry:

GitHub Container Registry (GHCR)


Image:

ghcr.io/isangare-ux/pacman-app/pacman-app:<tag>


Authentifizierung:

docker/login-action@v3


Verwendetes Token:

GITHUB_TOKEN


Das Token wird automatisch durch GitHub Actions
bereitgestellt.

Ein persönlicher Zugriffstoken (PAT) ist für die
Veröffentlichung nicht erforderlich.



==================================================
4. Image Pull aus GHCR
==================================================

Das veröffentlichte Image wurde anschließend aus der
GitHub Container Registry geladen.


Befehl:

docker pull \
ghcr.io/isangare-ux/pacman-app/pacman-app:e7c1216b2be3fc0549057c3e2cbf490f73d2b508


Ergebnis:

Das Image wurde erfolgreich heruntergeladen.


Digest:

sha256:c48904f298c583d156c59fc858207f3d54480d8bb6c1025a4a23d391d77ad1af



==================================================
5. Container Start und Smoke-Test
==================================================

Das aus GHCR geladene Image wurde lokal als Container
gestartet.


Beispiel:

docker run -p 8081:8080 \
ghcr.io/isangare-ux/pacman-app/pacman-app:<tag>


Anschließend wurde die Anwendung über HTTP geprüft.


Smoke-Test:

curl http://localhost:8081


Ergebnis:

Die Pacman-Anwendung wurde erfolgreich geladen.

Der erfolgreiche HTTP-Aufruf bestätigt, dass das aus
GHCR geladene Container Image funktionsfähig ist.
