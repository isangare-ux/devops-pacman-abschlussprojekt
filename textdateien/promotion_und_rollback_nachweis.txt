7. Begründung des GitOps-Verfahrens
Der Rollback wurde über Git durchgeführt, weil Git im Projekt die Quelle des gewünschten Systemzustands ist. Eine direkte Änderung im Cluster oder ein isolierter Argo-CD-Klick ohne passenden Git-Stand würde einen Unterschied zwischen dem in Git dokumentierten Sollzustand und dem tatsächlich laufenden Clusterzustand erzeugen.

Bei einem späteren Sync könnte Argo CD den weiterhin in Git gespeicherten fehlerhaften Zustand erneut anwenden. Durch git revert, Pull Request und Merge bleibt dagegen der korrigierte Sollzustand vollständig versioniert, prüfbar und reproduzierbar.

Der nachgewiesene Ablauf war:

Fehlerhafter GitOps-Stand
-> Argo CD synchronisiert Dev
-> ImagePullBackOff / ErrImagePull
-> keine Prod-Promotion
-> git revert
-> Rollback-Pull-Request
-> Merge nach main
-> Argo CD übernimmt korrigierten Git-Sollzustand
-> pacman-dev wieder Synced / Healthy

Prod blieb während des Fehlerfalls auf der freigegebenen Version Synced / Healthy.
